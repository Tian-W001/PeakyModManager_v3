# 角色时装维护

在 `scripts/characters.json` 的角色对象中配置可选的 `outfits` 数组。每项包含 `en` 和 `zh` 名称。

- `outfitId: 0` 表示“非时装”（None-Outfit），不占用 `outfits` 数组条目。
- 实际时装 ID 为数组下标加 `1`：`outfits[0]` 对应 ID `1`，`outfits[1]` 对应 ID `2`，依此类推。第一个数组条目是默认时装。
- 不提供数组或使用空数组时，角色隐含一套默认时装。
- 只有一套实际时装时，列表筛选和 Mod 详情中的时装选择都隐藏；“非时装”不计入实际时装数量。
- 后续新增时装必须追加到数组末尾。不要重排、插入到中间或删除已有条目，否则已保存的 Mod 会指向不同的时装。名称可以修改。
- 更新后运行 `npm run gen:characters`，同时提交生成的角色列表、时装数量表和中英文翻译。

角色 Mod 加载和保存时会规范化 `outfitId`：缺失、类型错误、非整数、负数或超出该角色时装范围时归到 `0`。
非角色 Mod 不保留 `outfitId`。目录新增时装后，未标注的 Mod 仍然属于“非时装”。

现有 ID 按上述规则解释，不自动加一迁移旧数据；原先保存的 `0` 现在表示“非时装”。

角色分类页左下角显示时装筛选菜单，顺序为“全部 → 各套时装 → 非时装”，初始选中“全部”。切换角色或分类会重置筛选。
Mod 详情中同样将“非时装”放在各套时装之后；修改角色会将时装重置为 `0`（非时装）。

应用在缓存恢复后比较当前应用版本和上次成功自动刷新的版本。版本不同（包括没有历史记录）时，会在打开列表前扫描 Mod 库并校验元数据，成功后一起缓存列表和版本号。同版本启动不重复扫描。
没有配置 Mod 库时跳过；目录不可用或任意 Mod 读取、校验、写入失败时保留旧缓存及版本记录，下次启动重试。发布更新时需要更新应用版本号才能触发这次自动刷新。
